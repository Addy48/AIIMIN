# Weaknesses

Only objective constitutional issues. No wording polish. No redesign.

### W1 — Layer stack claimed universal; actually ingress-primary

| Field | Value |
|-------|-------|
| **Section** | §2 Interaction Layers |
| **Problem** | Stack presented as pipeline for “every meaningful exchange,” but linear Intent→Catch→Understanding→Decision→Presentation→Execution→Learning fits **ingress**. Review (`Recall → Orient → Act`), Knock (`Knock → Dismiss\|Act`), Hand-back, and Offline recovery do not travel that order. Presentation (attention) often precedes Decision on review paths. Settle is produced by Layer 2 **and** Layer 6. |
| **Why it matters** | Downstream will force every flow through Catch or invent silent exceptions — both break predictability (IP-01) and Exhale scope clarity. |
| **Minimal remediation** | Declare stack as **ingress default**. Add one sentence: non-ingress classes use **legal subsequences** of layers (cite P8 review / AI / recovery contracts). State Settle as **cross-layer outcome**, not Layer-2-only. |

### W2 — Object catalog mixes interaction primitives with life-entity subclasses

| Field | Value |
|-------|-------|
| **Section** | §3.1 Document, Event (+ Task/Action vs Entity) |
| **Problem** | Document and Event are Ch 05 life-entity classes, not interaction participants distinct from **Entity**. Task/Action overlaps Entity + Act verb. Catalog is not orthogonal. |
| **Why it matters** | Hidden ownership conflict with P8 Ch 05. Future phases will mint parallel object systems. |
| **Minimal remediation** | Keep Entity as the graph object. Demote Document / Event / Task to **entity kinds** (examples under Entity), not peer interaction objects. Keep interaction objects = Pulse, Offer, Chip, Anchor, Veil, Hold, Hand-back, Suggestion, Thread, Notification, Reminder, Conversation, Review (session), Capture (pipeline) — if Capture retained (see W3). |

### W3 — Capture-as-object sits next to Catch (drift risk)

| Field | Value |
|-------|-------|
| **Section** | §3.1 Capture (system object) |
| **Problem** | Even with notes, Capture as named interaction object competes with Catch verb and Capture outcome (Ch 02/06). Three senses of “capture” in one architecture. |
| **Why it matters** | Highest-probability vocabulary failure mode against P8 Ch 09 lock. |
| **Minimal remediation** | Rename object to **Ingress Pipeline** / **Catch Session** (Founder pick one), **or** mark Capture object as **non-speakable in interaction grammar** (engineering-only alias to Ch 06). |

### W4 — Triple ontology: same term as object + verb + state

| Field | Value |
|-------|-------|
| **Section** | §3 + §4 + §6 (Hold, Veil, Hand-back, Review, Settle, Offer, …) |
| **Problem** | P8 vocabulary allows noun/verb duality; P9 adds full object lifecycles **and** constitutional states **and** verbs without an explicit ontology rule. |
| **Why it matters** | Implementers cannot answer: “Is Hold a state, an object, or both?” Ambiguity becomes accidental UX doctrine. |
| **Minimal remediation** | Add one **Ontology law**: each term has primary class (Verb \| State \| Object) and secondary allowed uses. Example: Hold = State primary; Veil = State+Object; Hand-back = Verb primary; Review = Object (session) primary, verb secondary alias of entering that object. |

### W5 — Verb inflation / outcome verbs / duplicates

| Field | Value |
|-------|-------|
| **Section** | §4.2 Connect, Coach, Execute, Undo, Search/Ask, Create |
| **Problem** | (a) **Connect** and **Coach** are P8 existence **outcomes**, not P8 interaction verbs — verbizing them risks synonym drift with Thread-chip / Knock. (b) **Execute** ≈ Act. (c) **Undo** ≈ Hand-back (Law of Verb Truth pressure). (d) **Search** and **Ask** glued despite different jobs. (e) **Create → Offer** without mandatory Catch allows structure-first path that can shadow Exhale if taught as peer ingress. |
| **Why it matters** | Grammar bloat + constitutional drift from P8 verb set; Create can become taxonomy-first by another name. |
| **Minimal remediation** | Connect/Coach → outcomes only (or reserved, non-sentence verbs). Drop Execute (use Act) or define Execute as system-internal non-grammar. Undo → platform synonym only, not catalog peer. Split Search vs Ask. Create: MUST declare relationship to sacred spine (structure-first Create still requires raw Settle of something, or is explicitly non-ingress). |

### W6 — Catch → Veil and Commit-by-Drift under-specified

| Field | Value |
|-------|-------|
| **Section** | §4.2 Catch, Commit, Drift |
| **Problem** | Catch allows Veil (“rare”) with no trigger definition. Commit owner allows “legitimate Drift rules” without stating those rules. Drift allowed-to lists **Resume** but Resume is not a verb. |
| **Why it matters** | Ambiguous transitions become loopholes against Offer-before-Settle and silent discard bans. |
| **Minimal remediation** | Either remove Catch→Veil or define the single allowed trigger. Forbid Commit-by-Drift until Drift/Commit rules written. Add Resume verb **or** remove Resume from Drift exits. |

### W7 — Loading mapped to Hold (axis collapse)

| Field | Value |
|-------|-------|
| **Section** | §5.1 Loading |
| **Problem** | “MUST map to Hold or Thinking” collapses runtime **Loading** into constitutional **Hold**. Hold means durability/inference honesty (P8). Shell fetch Loading is not Hold. |
| **Why it matters** | Directly undermines dual-axis model (C2 family). Teams will paint spinners as Hold or inflate Hold into all waiting. |
| **Minimal remediation** | Loading stays runtime condition only. Hold only when durability/inference truth is pending. Thinking only for AI Understanding/Coach prep. |

### W8 — Dual-axis missing impossible-combination matrix

| Field | Value |
|-------|-------|
| **Section** | §6.2–6.3 |
| **Problem** | C1–C8 help, but legal/illegal pairs incomplete (e.g. Catch+Success, Veil+Thinking, Knock+Offline, Settle+Failed, Review Required vs Reflect). Hold vs Partial vs Failed boundaries soft. |
| **Why it matters** | Without forbid matrix, every interaction cannot be reliably represented — Phase readiness fails. |
| **Minimal remediation** | Add short **forbidden pairs** table (≥8 rows) + one sentence distinguishing Hold / Partial / Failed / Conflict. |

### W9 — Success runtime condition threatens Settle honesty

| Field | Value |
|-------|-------|
| **Section** | §6.2 Success · Founder Q6 |
| **Problem** | Transient “Success” next to Settle invites Settle-chrome reuse (already warned in C2). |
| **Why it matters** | Trust philosophy and Law of Settle. |
| **Minimal remediation** | Ban Success as named condition **or** rename to **Acknowledged** and bind exclusively as non-durable flash after true Settle — never during Hold. |

### W10 — Accessibility interaction under-represented

| Field | Value |
|-------|-------|
| **Section** | §5 Universal Rules · §7 Principles |
| **Problem** | P8-R-148 / GOV-133 treat accessibility as interaction quality. Phase 1 has focus-order note only; no foundational a11y interaction principle. |
| **Why it matters** | Gaps become “later UX,” which P8 forbids for critical paths. |
| **Minimal remediation** | Add one universal rule + one IP (or fold into IP-10): critical-path operability, announcements of Settle/Hold/Failed, non-gesture-only Catch/Veil — cite P8-R-147/148. No UI detail. |

### W11 — Philosophy imports numeric confidence bands

| Field | Value |
|-------|-------|
| **Section** | §1.4 AI-first |
| **Problem** | ≥70% / 40–70% / <40% are Ch 07 AI Architecture thresholds living inside interaction philosophy. |
| **Why it matters** | Minor — not fatal — but makes philosophy look implementation-specific; band changes would appear to amend P9 philosophy. |
| **Minimal remediation** | Replace numbers with “confidence bands per P8 Ch 07”; keep behavioral meanings (auto-fill+correct / confirm / ask / never infer). |
