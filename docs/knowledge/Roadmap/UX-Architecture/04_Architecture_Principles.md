# 04 — Architecture Principles

Governing principles for all UX Architecture work. Not a Design System. Not UI rules.

## P-UXA-01 — Law before layout

Genesis (esp. P8 product law, P9 interaction law, P5 constitution) is supreme. Architecture **expresses** law. Architecture **never** amends it.

## P-UXA-02 — Evidence only

UX Intelligence is the **sole** evidence source for what the product currently is. Program 0 supplies readiness/gap context. No repo re-discovery that invents facts against Intelligence without Founder amendment of Intelligence.

## P-UXA-03 — No invention

Never invent functionality, journeys, surfaces, or scope. Architecture may **classify, structure, and target** what Intelligence already recorded (KEEP / REDESIGN / MERGE / REMOVE / FUTURE).

## P-UXA-04 — Expression ≠ redesign approval

Intelligence Opportunities (O*) and Debt (D*) are inputs. Architecture may propose structural resolutions. Visual redesign, component kits, and eng work stay out of this program.

## P-UXA-05 — Traceability mandatory

Decision without Genesis + Intelligence citations is invalid.

## P-UXA-06 — Cross-surface honesty

Three clients (desktop web · `/m` · native) are first-class. Ceilings (esp. `/m` capture-only) bind architecture. Open Founder exceptions (D05) stay explicit — never silently assumed.

## P-UXA-07 — Day spine primacy

Per Genesis Day / Intelligence alignment: Today (day surface) is architectural primary — not a generic dashboard dump. Naming debt (Today vs `/overview`) is architecture-owned to resolve structurally.

## P-UXA-08 — State completeness

Loading · empty · error · offline · permission · sync · conflict · AI processing are architectural concerns derived from Intelligence State Inventory — not optional polish.

## P-UXA-09 — Calm recovery

Errors and recovery paths are part of architecture (Intelligence journeys: recovery weak). Architecture defines required recovery structure; copy kits may follow in Content/DS.

## P-UXA-10 — Downstream humility

UX Architecture does not ship tokens, components, APIs, or screens-as-law. It hands **contracts** to Design System · Motion · Engineering · AI Architecture · Implementation under P9 DH.

## P-UXA-11 — Parallel launch ops

Program 0 launch priorities may run in parallel. Architecture must not block launch ops falsely — and launch ops must not silently change UX law without Intelligence/Architecture update.

## P-UXA-12 — Stop discipline

Work only authorized phase. Initialization stops at charter/principles/validation. Further bodies need Founder continuation.
