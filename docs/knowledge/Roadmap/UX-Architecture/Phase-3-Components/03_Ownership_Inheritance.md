# 03 — Ownership and Inheritance

## Ownership matrix

| Family / Tier | Architectural owner | Consumers | Must not own |
|---------------|---------------------|-----------|--------------|
| T0 Primitives | System / Design System downstream | All web domains | Domain business rules |
| T1 Feedback | System | All | Domain copy invention without content kit |
| T2 Nav | Shell | App frames | Domain feature logic; `/m` score |
| T3 Capture | Capture domain + System logger | Today · `/m` · Journal | Structure ceremony wrappers |
| T4 Rows | Owning domain (Habits, Family…) | That domain (+ shared if extracted) | Parallel row for same entity |
| T5 Metric | Growth/Day read | Today · Reports | Capture write UI |
| T6 Charts | Derived domains (Finance/Reports/Sports) | Those domains | Identity/brand system |

## Inheritance rules

| Rule | Meaning |
|------|---------|
| **IH-1** | Variants inherit parent **behavioral + a11y contract**; they do not fork a second primitive (C-3) |
| **IH-2** | Domain components may compose T0–T1; they must not reimplement Confirm/Empty/Skeleton |
| **IH-3** | Native T10 inherits **contracts** from T0–T3 conceptually; not DOM inheritance |
| **IH-4** | Marketing T8 does not inherit Life OS Metric/Nav contracts into waitlist (isolation) |
| **IH-5** | Metric MERGE: HeroMetricCard / MetricTile / Metric → one inheritance tree with size/context variants only |
